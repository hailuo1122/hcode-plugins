# 做自己的插件，分享给别人

这份指南写给所有 HCode 用户。不会写代码也没关系 —— 让 HCode 帮你写。
做完之后，**分享分两条路**：直接把仓库给朋友（最轻量），或收录进社区市场让所有人发现。

## 第一步：让 HCode 帮你做出插件

1. 在 HCode 里新开一个会话，直接说：

   > 帮我做一个插件：<一句话说明你要它干什么>

   HCode 会用内置的 `plugin-creator` 能力生成插件骨架：
   `.zcode-plugin/plugin.json`（插件清单）+ 一个示例技能 + README，并登记到本地 dev 市场。

2. 跟着它的引导把你的需求讲清楚（插件叫什么、需要哪些能力、触发场景是什么）。
   它会把改动落在你指定的目录里，随后帮你校验。

> 会写代码的话也可以手写；清单字段与目录结构见 `plugin-creator` 技能里的 `references/plugin-json-spec.md`。

## 第二步：先在本地试用

1. HCode → 设置 → 插件市场 → 添加市场，填入骨架所在目录的**本地路径**。
2. 安装插件，在对话里触发一次它声明的能力，确认行为符合预期；不满意就改，改完在商店里点「更新」再试。

## 第三步：上传到 GitHub

1. 建一个仓库（建议 public），把插件目录推上去：

   ```sh
   cd <插件目录>
   git init && git add -A && git commit -m "feat: <插件名>"
   git remote add origin https://github.com/<你的账号>/<仓库名>.git
   git push -u origin main
   ```

2. 确认仓库根目录有 `.zcode-plugin/plugin.json`（骨架已生成）。
3. 打个 release tag（推荐 `v0.1.0` 这类格式）。别人可以钉在这个版本上安装，
   你之后的改动不会影响已分享出去的版本。

## 给你的插件配个图标（可选）

不配也能收录，但配了在商店里更容易被认出来。两种方式，任选其一：

1. **放仓库里（推荐，零配置）**：在插件仓库的 `.zcode-plugin/` 目录下放一个
   `icon.png`（或 `icon.svg` / `icon.webp`），建议正方形 ≥256×256。
   索引构建时会自动使用它（通过 jsDelivr 按你钉的版本分发）。
2. **写在条目里**：在 `plugins/<插件名>.json` 里加 `"icon": "https://..."`（任意 https 图片地址）。

都没有时，商店会回退显示你 GitHub 账号的头像。

## 分享方式 A：把仓库地址给朋友（最轻量）

无需任何人审核。朋友在 HCode → 设置 → 插件市场 → 添加市场，填：

```
<你的账号>/<仓库名>
```

可选加 `#v0.1.0` 钉住版本。订阅后商店里就能看到并安装你的插件。

适合：面对面分享、小圈子试用、还在迭代中的插件。

## 分享方式 B：收录进社区市场（所有用户都能发现）

社区市场（市场 id `hcode-community`）是 HCode 内置的公开源之一，
目录由本仓库（社区索引仓库）维护。收录 = 提一个 PR：

1. Fork 本仓库
2. 在 `plugins/` 下新增 `<插件名>.json`（模板见 `templates/plugin-entry.json`）：

   ```json
   {
     "name": "your-plugin",
     "description": "一句话说明这个插件做什么",
     "source": { "source": "github", "repo": "<你的账号>/<仓库名>", "ref": "v0.1.0" },
     "author": "你的账号"
   }
   ```

   - 文件名、`name`、插件仓库里 `plugin.json` 的 `name` 三处必须一致
   - `ref` 钉 release tag（或 `sha`），保证用户装到的版本可复现
3. 提 PR。CI 自动机械校验：仓库可达、版本钉可达、插件名一致。
4. 合并后，所有 HCode 用户的商店「公开」分段里都能搜到你的插件。

**更省事的路**：给插件仓库打上 GitHub topic **`hcode-plugin`**，
每日发现任务会自动扫描并帮你开候选 PR（仍需一次合并确认）。

字段的完整说明与常见报错对照见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 发布新版本

1. 改代码 → 把 `plugin.json` 里的 `version` 加一 → 打新 tag（如 `v0.2.0`）推送。
2. 方式 A（直接分享）：让朋友把来源里的 `#ref` 改成新 tag，或在商店里点「更新」。
3. 方式 B（索引收录）：给本仓库提 PR 把条目里的 `source.ref` 更新到新 tag；
   条目未钉版本时，用户端直接点「更新」即可拿到最新内容。

## 边界与礼貌

- 社区市场是「指针 + 机械校验」：**收录 ≠ 安全背书**。CI 只检查可达性与名称一致性，不审代码。
- 插件以安装者的权限运行。请在插件 README 里写清楚它会读写什么、需要哪些权限、要不要联网，方便别人判断。
- 想下架：提 PR 删除 `plugins/<插件名>.json` 即可（方式 A 的分享本来就不经过索引）。
- 发现别人的插件有问题：开一个 `report-plugin` issue。
